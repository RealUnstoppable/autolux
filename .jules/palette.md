## 2024-05-23 - Interactive Divs Missing Accessibility
**Learning:** The application uses custom `div` elements for core interactions (like the mobile menu toggle in `index.html`) without proper roles, tabindex, or keyboard event listeners, making them inaccessible to screen readers and keyboard users.
**Action:** Always ensure custom interactive elements have `role="button"`, `tabindex="0"`, appropriate `aria-*` attributes (like `aria-expanded`), and keyboard event handlers (Enter/Space), or preferably, use semantic `<button>` elements.
## 2024-05-20 - Custom Div Forms
**Learning:** The codebase occasionally uses custom `div` containers with inline `onclick` buttons for forms (like newsletter signups) instead of semantic `<form>` elements, breaking keyboard accessibility (native "Enter" submission).
**Action:** When working with text input and submit flows, always wrap the elements in a semantic `<form>` to inherit native "Enter" key submission behaviors.
## 2024-06-10 - Enhance Form Accessibility and Auto-completion
**Learning:** Adding standard `autocomplete` attributes (like `name`, `email`, `tel`, `current-password`) significantly improves UX by allowing browser autofill and password managers to assist users. Furthermore, ensuring that visually required asterisks use `aria-hidden="true"` prevents screen readers from reading them as "star", while `aria-required="true"` accurately conveys the requirement. Dynamic feedback messages (like form submission responses) should use `aria-live="polite"` so they are announced by screen readers without interrupting the user. Additionally, phone number inputs should use `type="tel"` to trigger the correct mobile keyboard.
**Action:** Always include appropriate `autocomplete` attributes on standard form fields. When creating custom required indicators, hide them from screen readers and use ARIA properties. Apply `aria-live="polite"` to dynamically updating text nodes (unless it's a character counter where it would be annoying), and ensure inputs use the most semantically appropriate `type` (like `tel` for phones).
